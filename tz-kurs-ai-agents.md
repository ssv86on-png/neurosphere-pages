### Модуль 3: Серверная инфраструктура для агентов
*Время: 1.5 часа*

**Теория (30 мин):**
- Выбор хостинга: VPS vs Mac Mini vs Local
- Характеристики: 4-8 CPU, 8-16 ГБ RAM, 60-100 ГБ NVMe
- OS: Alpine Linux vs Debian/Ubuntu
- Docker: образы, контейнеры, volumes, сети
- Файловая система для агента: /opt, /data, /workspace

**Практика (45 мин):**
- Скрипт начальной настройки сервера для AI-агента:
  ```bash
  # Минимальный набор
  apk add docker docker-compose nginx git curl
  rc-update add docker default
  service docker start
  
  # Структура директорий
  mkdir -p /opt/agents/{shared-memory,backups,workspace}
  ```
- Docker Compose для агента:
  ```yaml
  version: '3'
  services:
    agent:
      build: .
      volumes:
        - ./workspace:/workspace
        - ./shared-memory:/shared-memory
      environment:
        - LLM_API_KEY=${LLM_API_KEY}
        - TELEGRAM_BOT_TOKEN=${TELEGRAM_BOT_TOKEN}
      restart: unless-stopped
  ```
- Мониторинг: `htop`, `df -h`, `docker stats`, `journalctl`

**Питфоллы:**
- Alpine не имеет systemctl — используй `rc-service`
- Docker из контейнера не имеет SSH на хост — используй API
- Telegram-токены не копировать между профилями

### Модуль 9: Безопасность и 152-ФЗ — Обезличивание данных
*Время: 1 час*

**Теория (20 мин):**
- 152-ФЗ «О персональных данных»: что считается ПД
- Техники обезличивания:
  - Маскирование: «Иван Иванов» → «И*** И***»
  - Хеширование: hash(email + salt)
  - Псевдонимизация: замена на уникальный ID
  - Агрегация: средние/суммы вместо точных значений
- Риски: утечка ПД через LLM API (OpenRouter, Anthropic, OpenAI)

**Практика (40 мин):**
- Реализация функции обезличивания:
  ```python
  import re
  import hashlib
  
  def anonymize(text, salt="project_salt_2026"):
      # Маскировка email
      text = re.sub(r'[\w.+-]+@[\w-]+\.[\w.]+', '[EMAIL_OBFUSCATED]', text)
      
      # Маскировка телефона
      text = re.sub(r'\+?\d[\d\s()-]{7,15}\d', '[PHONE_OBFUSCATED]', text)
      
      # Маскировка ФИО (кириллица, 3 слова с заглавной)
      text = re.sub(r'\b[А-Я][а-я]+\s[А-Я][а-я]+\s[А-Я][а-я]+\b', '[FULL_NAME]', text)
      
      # Хеширование строк, похожих на ID
      ids = re.findall(r'\b(?:user|customer|client|order)_\d+\b', text, re.I)
      for id_str in ids:
          hashed = hashlib.sha256((id_str + salt).encode()).hexdigest()[:12]
          text = text.replace(id_str, f'id_{hashed}')
      
      return text
  ```
- Интеграция в пайплайн агента: перед отправкой в LLM → anonymize → после ответа → deanonymize
- Настройка YandexGPT для госсектора: использование IAM-токенов, сертифицированные дата-центры

**Кейсы (из Enterprise AI Facilitator Blueprint):**
- **Госзакупки через AI:** обезличенные данные коммерческих предложений → анализ → рекомендации
- **Медицинские учреждения:** анонимные данные пациентов → диагностика → статистика
- **Банки:** обезличенные транзакции → поиск аномалий → фрод-мониторинг

**Лабораторная работа:** Написать функцию обезличивания, протестировать на реальных данных, интегрировать в агента.

### Модуль 10: Масштабирование — От 1 до 100 агентов
*Время: 1 час*

**Теория (20 мин):**
- Когда нужен 1 агент, когда 10, когда 100
- Инфраструктура на N агентов:
  - 1 сервер: 4-5 агентов (лёгкие, без своих LLM)
  - 10 серверов: Kubernetes (k3s)
  - 100+ агентов: RabbitMQ + микросервисная архитектура
- Ресурсы на 1 агента: ~300-500 МБ (без своей нейросети), ~4-5 ГБ (с нейросетью 7B)

**Практика (30 мин):**
- Оркестрация задач через GitHub Issues / GitLab
- Docker Swarm или k3s для роя агентов
- Мониторинг: Prometheus + Grafana для дашборда агентов
- CI/CD для навыков: обновление SKILL.md через git push

**Питфоллы (из практики):**
- ollama жрёт 6.5 ГБ на образ и 4+ ГБ RAM на модель 7B
- Telegram CONFLICT при рестарте — ждать 10 сек
- session_search ищет во всех сессиях — может быть медленно на 1000+ сессиях

**Лабораторная работа:** Запустить 3 агента на одном сервере, настроить мониторинг.

### Модуль 11: Внедрение в бизнес — Реальные кейсы и ROI
*Время: 1.5 часа*

- Метрики внедрения AI-агента:
  - Сокращение времени на рутину: 60-80%

## 5. ФИНАЛЬНЫЙ ПРОЕКТ

Студент развёртывает систему из 2+ агентов, которые:
1. Работают на одном VPS-сервере
2. Каждый со своим Telegram-ботом
3. Обмениваются данными через общее файловое хранилище
4. Обезличивают ПД перед отправкой в LLM
5. Реализуют heartbeat-мониторинг друг друга
6. Auto-restart при падении
7. Выполняют одну бизнес-функцию (на выбор студента)

**Критерии приёмки:**
- Оба агента отвечают в Telegram
- Один агент может поставить задачу другому через /shared-memory
- В памяти видны сессии за последние 7 дней
- Функция обезличивания работает
- При остановке одного агента — второй продолжает работу
